# 观察分析上下文与定向纠错修复验收

2026 年 10 月 20 日的连续失败集中在同一份两人观察。模型将活动名称、时机、目标、教师角色等字段生成成单字片段；既有校验拒绝这些片段，整份重生成又增加了失败与超时机会。

## 修复内容

园本参考上下文限制为序列化后最多 8000 字符、最多 6 项，每项摘要最多 500 字符、相关片段最多 700 字符。片段按当前主题、场景、聚焦和白描词组匹配，不再注入知识全文。教师原始观察、补充事实与历史证据不受这项裁剪影响。

观察提示词升级至 `observation-analysis.qwen.v12`。完整短句要求同时应用于园所自定义提示词，明确活动名称、时机、目标、角色、材料用途、参与和退出条件的写法，并区分未来建议与已发生事实。

过短的未来应答字段使用一次定向纠错请求：携带字段实际值、类型和长度约束，只允许返回列出的修正键。合并时仅修改对应应答路径，事实、经验判断与证据编号保留；修正后重新执行完整结构、证据、安全和方案区分校验。其他格式故障仍保留一次有具体约束的完整纠错；超时不自动重复昂贵请求。失败草稿不会序列化到应用日志。

每次请求生成独立证据编号白名单并写入 JSON Schema 枚举。未实际送入模型、且无可读转写的附件不能被引用为画面事实。诊断新增园本上下文裁剪前后字符数，便于追查后续异常。

## 单字输出复核与根因修正

18:25 复核发现，18:05:46 发起、18:08:50 完成的客户重试虽然两个幼儿均为 completed，但两人的 18 条活动步骤全部是单字，提问、观察重点等也有单字。事实和解释长度正常。原验收只确认既有结构、证据和流程校验通过，遗漏了允许 minLength=1 的文字列表，不能将之前的成功状态视为建议内容完整。

已用同一 YT 密钥与 `qwen3.7-plus-2026-05-26` 完成三组最小对照。要求原样返回两条完整步骤和一条介入时机，仅改变 JSON Schema pattern：旧规则 `[A-Za-z\\u3400-\\u9FFF]` 返回单字“师”“儿”，还使相邻的时机字段退化为单字；移除 pattern 和改用包含完整前后文的 `^[\\s\\S]*[A-Za-z\\u3400-\\u9FFF][\\s\\S]*$` 都逐字返回完整原句。三次均 HTTP 200、finish_reason=stop、约 1–2 秒。该对照再次运行得到相同结论，证明问题来自远端约束解码对原单字符 pattern 的处理，而非本地页面截断或生成 token 耗尽。园本文本过长会增加成本和风险，但不是单字问题的充分解释。

最终移除公共文字列表的远端 pattern，由本地检查文字语义完整性，避免约束解码的正则兼容问题；在新观察生成入口增加独立完整性校验：活动步骤与提问每项至少 8 字，观察重点至少 4 字，目标经验至少 2 字，其他建议按字段约束写完整短句。远端 Schema 与本地校验使用同一组规则。原始事实、合法证据编号、已有结果的读取规则及“纸”等合法单字材料名不受这些生成约束影响。提示词升级为 v13，补充完整步骤和条件式提问示例。

定向纠错将同一列表的多个单字合并为一个待修列表，支持超过 100 个问题项，仍只进行一次有限纠错。合并后重新执行完整生成校验、证据回链、安全和方案区分检查；不修改事实、解释或证据编号。无法修好的内容不会作为成功结果保存。

新增回归覆盖：远端不再携带单字符正则、完整句子和换行在本地校验中合法、真实单字列表被拦截且历史仍可读、102 个单字问题合并为 15 个列表后一次纠错完成或明确失败。`npm run check` 通过 108 项 API 和 48 项前端测试、98/96 路由契约、API 与两种前端构建及生产数据边界检查。只读复验脚本增加单字步骤/提问/重点注入开关；HTTP 验收现在校验最终保存文字的完整性，不再只检查方案数量。
