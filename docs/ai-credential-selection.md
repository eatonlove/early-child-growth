# 千问密钥选择

## 使用方法

教研员进入“提示词配置 → 千问 API 密钥”，选择名称并点击“保存密钥选择”。

- YT：原有密钥，仍为默认选项。
- YQY：新增密钥。
- 所有AI场景共用本园所的选择，模型配置保持独立。
- 下一次任务开始时生效；进行中的任务及其重试保持原密钥。
- “已配置”只说明后端已设置标准密钥，不保证该账号的余额、配额或模型权限。
- 不自动切换另一密钥，不会自动重跑历史结果。

## 后端配置

YT继续读取 `QIANWEN_API_KEY`，兼容 `DASHSCOPE_API_KEY`；YQY读取 `QIANWEN_API_KEY_YQY`。真实值仅放在受限权限的后端环境文件中，不进入Git、浏览器构建或数据库。新增名称之外的密钥需由维护人员补充配置，不向教师提供查看密钥接口。

数据库 `tongji_v3.ai_credential_configs` 仅存名称、园所、修订号和修改人。启用RLS，撤销匿名和普通认证角色的直接表访问，只允许后端服务角色经教研员接口访问。保存时校验名称、配置状态、园所身份和修订号，审计只记录名称。

解析提示词时读取园所名称，调用方固定该名称；同一任务的画面分析、输出修订和联网参考共用对应客户端。参考检索缓存按名称分开，不把密钥放入提示词、业务快照或API响应。

## 验证

- `npm run check`
- `npm --prefix apps/v3-local run test:e2e:production`
- `npm run local:up`
- `node scripts/verify-ai-credentials.mjs`
- 经明确授权后：`node scripts/verify-ai-credentials.mjs --production --authorized-production-fixtures`

最后两个脚本使用隔离的虚构园所和账号，验证教研员切换、教师拒绝、跨园隔离、并发冲突、刷新持久化、桌面1920/1440/1280布局以及YQY真实请求；结束后清理测试身份与配置，核对客户元数据不变。真实请求仅使用虚构文字，不上传幼儿资料；不代表已重新验收长视频耗时或所有模型额度。
